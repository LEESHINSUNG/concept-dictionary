원격 코드 실행

Remote Code Execution (RCE) · リモートコード実行

원격 코드 실행은 멀리 있는 공격자가 남의 서버에서 자기가 원하는 명령을 돌릴 수 있게 되는 것이에요. 취약점 가운데 가장 무거운 축에 들어요.

작성일 2026-10-29 카테고리 보안 › 취약점

1

쉽게 말하면

식당 주문서에 "김치찌개 하나"라고 적어야 하는데, 누군가 "김치찌개 하나, 그리고 금고 열어 줘"라고 적었다고 해 봐요. 주방이 주문서를 의심 없이 그대로 따르면 금고가 열려요.

서버도 똑같아요. 밖에서 들어온 값을 데이터로만 다뤄야 하는데, 실수로 그 값을 명령으로 실행해 버리는 틈이 있으면 공격자는 서버 앞에 앉은 것처럼 무엇이든 시킬 수 있어요. 이게 RCE예요. "원격"은 공격자가 그 컴퓨터에 손대지 않고 네트워크 너머에서 한다는 뜻이에요.

공격자의 발판

정보 빼내기, 악성코드 심기, 다른 서버로 건너가기

1공격자는 검색창, 파일 업로드, 요청 헤더처럼 서버가 받아 주는 곳에 평범한 값 대신 명령을 섞어 보내요.

2서버 프로그램에 틈이 있으면 그 값이 서버의 권한으로 실행돼요. 로그인도, 사용자의 클릭도 필요 없는 경우가 많아요.

3한 번 실행이 되면 공격자는 서버를 자기 것처럼 써요. 그래서 RCE 취약점은 CVSS 점수가 최고 수준으로 매겨지는 일이 흔해요.

3

직접 해보기

RCE가 생기는 가장 흔한 길은 명령 주입이에요. 내 컴퓨터 터미널에서, 해가 없는 echo로 원리만 살펴볼게요.

터미널

# 누군가 이름 칸에 이렇게 적었다고 해요
$ name='철수; echo 해킹됨'
# 위험: 입력을 명령 문장에 그대로 끼워 셸에 넘겨요
$ sh -c "echo 안녕 $name"
안녕 철수
해킹됨
# 안전: 입력은 끝까지 글자로만 다뤄요
$ printf '%s\n' "안녕 $name"
안녕 철수; echo 해킹됨

위험한 쪽에서는 ; 뒤가 새 명령으로 실행됐어요. 여기선 echo였지만, 실제 공격에서는 이 자리에 파일을 지우거나 악성코드를 내려받는 명령이 들어가요. 안전한 쪽은 같은 입력을 그냥 글자로 찍었을 뿐이에요.

실제 사례 · Log4Shell

2021년 12월, 자바 프로그램이 널리 쓰는 기록 도구 Log4j에서 RCE가 발견됐어요(CVE-2021-44228). 로그에 특정 문자열이 남기만 해도 원격에서 코드가 실행됐고, CVSS 점수는 만점인 10.0이었어요. 공개 직후부터 실제 공격이 쏟아졌어요.

뚫린 다음에 벌어지는 일

공격자는 빼앗은 서버에 악성코드를 심어 봇넷의 일원으로 만들고, C&C 서버에서 명령을 받게 해요. 패치가 나오기 전에 노리면 제로데이 공격이 되고요.

막는 방법

입력은 명령에 끼워 넣지 않기가 첫째예요. 그다음은 패치를 빨리 적용하고, 서버 프로그램은 꼭 필요한 권한만 갖고 돌게 해요. WAF나 IPS는 알려진 공격 문자열을 앞단에서 걸러 시간을 벌어 줘요.

XSS도 "남의 코드가 실행되는" 공격이지만, 실행되는 곳이 방문자의 브라우저예요. RCE는 서버 자체에서 실행되므로 피해 범위가 훨씬 넓어요.

한 줄 정리

들어온 값이 명령이 되는 순간, 서버는 남의 것이 돼요.
