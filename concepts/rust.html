Rust

러스트 · Rust programming language

Rust는 C·C++만큼 빠르면서도, 메모리 실수를 컴파일할 때 막아 주는 프로그래밍 언어예요. 실행해 보기 전에, 터질 코드를 먼저 걸러내요.

1

쉽게 말하면

프로그램은 일하는 동안 메모리라는 책상을 빌려 써요. 다 쓰면 치워야 하죠. 언어마다 누가 치우느냐가 달라요. C·C++은 프로그래머가 직접 치워요. 빠르지만, 깜빡하거나 이미 치운 자리를 다시 쓰면 사고가 나요. Python·Java는 청소부(가비지 컬렉터)가 돌아다니며 치워 줘요. 편하지만 청소하는 동안 잠깐씩 멈추고, 그만큼 느려요.

Rust는 셋째 길을 골랐어요. 책상마다 주인을 딱 한 명 정해 두고, 주인이 자리를 뜨면 그 자리를 저절로 치워요. 그리고 "주인이 둘이 되는 코드", "치운 자리를 쓰는 코드"는 컴파일러가 아예 통과시키지 않아요. 그래서 청소부 없이도 빠르고, 사람이 실수해도 실행 전에 걸려요. 모질라에서 키워 2015년 5월에 1.0이 나왔어요.

메모리를 치우는 방식

주인 규칙 (소유권)

실수를 잡는 때

실행 전, 컴파일할 때

첫 정식판

1.0 · 2015-05-15

빠르다

청소부가 없어 C·C++에 가까운 속도가 나요. 실행 중에 멈칫하는 일도 없어요.

메모리 실수를 막는다

치운 자리 다시 쓰기, 두 번 치우기 같은 실수가 컴파일 단계에서 걸러져요.

동시 작업이 안전하다

여러 일꾼(스레드)이 한 값을 동시에 고치는 코드는 컴파일이 안 돼요.

도구가 하나로 모여 있다

cargo 하나로 프로젝트 만들기·빌드·테스트·라이브러리 설치까지 해요.

Rust의 심장인 소유권이 어떻게 돌아가는지예요.

a가 주인

값마다 주인은 언제나 하나예요

넘겨줘요move

b가 주인

이제 a로는 그 값을 못 써요

let b = a;

범위가 끝나면

저절로 치워요

주인이 하나라 누가 치울지 헷갈리지 않아요

&T

읽기만 빌려주기

여러 곳에 동시에 빌려줘도 돼요. 아무도 고치지 않으니까요.

&mut T

고쳐 쓰게 빌려주기

한 번에 딱 한 곳만. 그동안은 읽기 빌림도 안 돼요.

1값에는 주인이 한 명이에요. 다른 변수에 넘기면 주인이 바뀌고, 옛 주인은 더 이상 그 값을 못 써요.

2넘기지 않고 빌려줄 수도 있어요. 읽기는 여럿에게, 고치기는 한 명에게만. 이 규칙 덕분에 "누가 고치는 동안 누가 읽는" 사고가 생기지 않아요.

3이 규칙은 컴파일러 안의 빌림 검사기(borrow checker)가 실행 전에 전부 확인해요. 실행 중에는 아무것도 검사하지 않으니 속도를 잃지 않아요.

3

직접 해보기

Rust를 설치하면 cargo가 함께 깔려요. 새 프로젝트를 만들고 바로 돌려 볼 수 있어요.

터미널

$ cargo new hello
# hello 폴더와 기본 코드가 생겨요
$ cd hello
$ cargo run
# 빌드하고 바로 실행해요. 기본 코드라 이렇게 찍혀요
Hello, world!

이번엔 일부러 규칙을 어겨 볼게요. src/main.rs를 이렇게 바꾸고 다시 cargo run 해 보세요.

src/main.rs

fn main() {
    let a = String::from("책");
    let b = a;            // 주인이 b로 바뀌어요
    println!("{}", b);    // 괜찮아요
    println!("{}", a);    // 여기서 막혀요
}

컴파일러가 하는 말

error[E0382]: borrow of moved value: `a`

"이미 넘겨준 값을 빌리려 한다"는 뜻이에요. 다른 언어라면 실행 중에 터지거나 조용히 엉뚱한 값을 쓸 실수를, Rust는 실행 버튼을 누르기도 전에 막아요. 실제 메시지에는 몇 번째 줄에서 넘겼는지까지 함께 나와요.

1오랫동안 "빠르게"와 "안전하게"는 둘 중 하나였어요. C·C++을 고르면 속도를, Java나 Python을 고르면 안전함을 얻는 식이었죠.

2Rust는 안전 검사를 실행 중이 아니라 컴파일 때로 옮겨서 둘을 같이 잡았어요. 그 대가로 컴파일러가 깐깐해졌고요.

3메모리 실수가 왜 그렇게 문제냐면, 마이크로소프트(2019)와 크롬 팀(2020)이 각자 조사했을 때 심각한 보안 버그의 약 70%가 메모리 안전 문제였기 때문이에요.

5

장단점과 쓰이는 곳

장점

  • 빠르다청소부 없이 C·C++에 가까운 속도가 나요.
  • 실수를 미리 막는다메모리·동시 작업 사고를 실행 전에 걸러요.
  • 도구와 안내가 친절하다cargo 하나로 다 되고, 오류 메시지가 고칠 방법까지 알려 줘요.
  • 작은 곳에도 들어간다청소부가 필요 없어 커널이나 작은 기기에도 넣을 수 있어요.

단점

  • 배우기 어렵다소유권·빌림·수명 같은 다른 언어에 없는 개념을 익혀야 해요.
  • 컴파일이 느린 편이다검사를 많이 하는 만큼 빌드 시간이 길어요.
  • 빨리 대충 만들기엔 번거롭다시제품을 금방 만들 때도 규칙을 다 지켜야 해요.
  • 사람과 라이브러리가 아직 적다C·C++이나 Python만큼 오래 쌓인 자산은 없어요.

쓰이는 곳 1 · 다른 언어의 도구를 빠르게

파이썬 패키지 관리 도구 uv가 Rust로 만들어졌어요. 기존 도구보다 훨씬 빠른 이유가 여기 있어요. Rust 라이브러리는 crates.io라는 공개 저장소에 모이는데, 파이썬의 PyPI 같은 곳이에요.

쓰이는 곳 2 · 운영체제 안쪽

리눅스 커널은 오랫동안 C로만 써 왔는데, 2022년 12월에 나온 리눅스 6.1부터 Rust로 쓴 코드를 넣을 수 있게 됐어요. 메모리 실수가 곧 보안 구멍이 되는 곳이라 Rust가 잘 맞는 자리예요.

쓰이는 곳 3 · 브라우저 안에서

Rust 코드를 웹어셈블리(WebAssembly)로 바꾸면 브라우저에서 돌릴 수 있어요. 무거운 계산은 Rust가 맡고, 화면은 JavaScript가 맡는 식으로 나눠 쓰죠.

Stack Overflow의 2025년 개발자 설문에서 써 본 사람이 계속 쓰고 싶어 하는 언어(most admired) 1위였어요. 배우기는 어려워도, 익히고 나면 놓기 싫어지는 언어라는 뜻이에요.

한 줄 정리

빠른데 안전하게. 대신 컴파일러가 깐깐해요.
