프로토콜

protocol · 통신 규약

프로토콜은 서로 다른 기계가 말이 통하도록 미리 맞춰 둔 약속이에요. 무엇을 어떤 순서로 주고받을지 정해 둔 규칙 묶음이죠.

작성일 2026-10-21 카테고리 네트워크 › 기초 개념

1

쉽게 말하면

전화를 받을 때를 떠올려 보세요. 받는 쪽이 먼저 "여보세요", 그다음 거는 쪽이 용건, 끝에는 "들어갈게요". 양쪽이 같은 순서를 알고 있어서 대화가 되는 거예요. 한쪽이 갑자기 용건부터 말하면 어색해지죠.

기계들끼리도 똑같아요. 만든 회사도 운영체제도 제각각인데 서로 통하는 건, 먼저 무엇을 보내고 어떻게 답하는지를 문서로 못 박아 뒀기 때문이에요. 그 문서를 만드는 자리가 IETF고요. 그 약속이 프로토콜이에요. 웹은 HTTP, 메일은 SMTP, 주소를 찾는 건 DNS처럼 하는 일마다 따로 있어요.

1프로토콜은 글자 하나하나의 자리까지 정해 둬요. 오가는 패킷에서 어디까지가 주소이고 어디부터가 내용인지 양쪽이 똑같이 알아야 하니까요.

2순서도 정해요. 누가 먼저 말을 걸고, 어떤 답이 오면 다음으로 넘어가는지까지요.

3잘못됐을 때 어떻게 할지도 약속에 들어 있어요. 못 알아들었을 때 어떤 번호로 답할지 같은 것들이요.

3

직접 해보기

웹 브라우저가 평소에 주고받는 HTTP 대화를 그대로 꺼내 볼 수 있어요.

터미널

$ curl -v https://example.com 2>&1 | head -12
# > 로 시작하는 줄이 내가 보낸 말, < 로 시작하는 줄이 서버의 답이에요
# > GET / HTTP/1.1
# < HTTP/1.1 200 OK

첫 줄의 GET / HTTP/1.1이 "이 페이지를 HTTP 1.1 방식으로 주세요"라는 말이고, 200 OK는 "찾았어요"라는 약속된 번호예요. 404도 "그런 건 없어요"라는 뜻의 약속된 번호고요. 쿠키도 이 대화에 끼워 보내는 한 줄이에요.

한 줄 정리

같은 약속을 알아야, 말이 통해요.
