Docker는 프로그램을 실행에 필요한 것과 함께 '컨테이너'라는 상자에 담아, 어느 컴퓨터에서나 똑같이 돌게 해 주는 도구예요.

작성일 2026-10-29 카테고리 운영체제 › 컨테이너

1

쉽게 말하면

개발자들이 가장 많이 하는 말 중 하나가 "제 컴퓨터에선 되는데요?"예요. 내 노트북엔 Python 3.12가, 서버엔 3.9가 깔려 있는 식으로 환경이 조금씩 달라서 생기는 문제예요.

Docker는 이걸 밀키트처럼 풀어요. 재료(라이브러리), 양념(설정), 조리법(실행 명령)을 한 상자에 담아 두면, 어느 부엌에서 끓여도 같은 맛이 나죠. 그 상자의 설계도를 이미지, 실제로 끓고 있는 한 그릇을 컨테이너라고 불러요.

1Dockerfile에 "어떤 리눅스 위에, 무엇을 설치하고, 무엇을 실행할지"를 적어요. 사람이 읽을 수 있는 짧은 글이에요.

2이걸 구우면 이미지가 나와요. 이미지는 Docker Hub 같은 저장소에 올려 팀원·서버와 그대로 나눠 쓸 수 있어요.

3이미지를 실행하면 컨테이너가 돼요. 컨테이너끼리는 파일과 프로세스가 서로 안 보이게 칸막이가 쳐져 있어요.

3

직접 해보기

Docker Desktop을 설치한 뒤 터미널에서 해 봐요.

터미널

$ docker run hello-world
# 처음엔 이미지를 내려받고, 인사말이 찍혀요
Hello from Docker!
$ docker run -d -p 8080:80 nginx
# 웹 서버를 뒤에서 띄워요. 브라우저로 localhost:8080 을 열어 보세요
$ docker ps
# 지금 도는 컨테이너 목록과 ID가 나와요
$ docker stop 컨테이너ID

-d는 컨테이너를 백그라운드로 돌리라는 뜻이고, -p 8080:80은 "내 컴퓨터의 8080번 문으로 오면 컨테이너의 80번 문으로 넘겨라"는 뜻이에요. 웹 서버를 설치한 적이 없는데도 몇 초 만에 떠요.

왜 리눅스 이야기가 나올까

컨테이너의 칸막이는 리눅스 커널의 기능으로 만들어요. 그래서 맥과 윈도우의 Docker Desktop은 안쪽에 작은 리눅스 가상 머신을 하나 띄우고 그 위에서 컨테이너를 돌려요. 서버는 원래 리눅스라 바로 돌고요.

어디에 쓰나

신입이 첫날 개발 환경을 한 줄로 갖출 수 있고, 테스트한 이미지를 그대로 서버에 올려 "여기선 되는데 저기선 안 돼요"를 줄여요. 클라우드에서도 컨테이너 단위로 앱을 올리는 방식이 흔해요.

조심할 점

컨테이너는 커널을 함께 쓰기 때문에, 칸막이가 가상 머신보다 얇아요. 남이 올린 이미지는 출처를 확인하고, 이미지 속 프로그램도 CVE가 나오면 새로 구워야 해요.
