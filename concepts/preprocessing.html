카페 판매 기록 sales_raw.csv를 pandas로 다듬어 볼게요. 빈 금액 한 칸, 똑같은 줄 하나, 앞에 공백이 붙은 메뉴 이름이 섞여 있어요.

main.py

import pandas as pd

df = pd.read_csv("sales_raw.csv")
print(df.shape)                      # 몇 줄 몇 칸인지
print(df.isna().sum())               # 칸마다 빈 값이 몇 개인지

df = df.drop_duplicates()                                  # 중복 줄 지우기
df["메뉴"] = df["메뉴"].str.strip()                          # 앞뒤 공백 없애기
df["금액"] = pd.to_numeric(df["금액"].astype(str).str.strip(), errors="coerce")  # → 숫자
df["금액"] = df["금액"].fillna(df.groupby("메뉴")["금액"].transform("median"))
df["날짜"] = pd.to_datetime(df["날짜"])                      # 글자 → 날짜

print(df.shape)
print(df["금액"].mean())             # 이제야 믿을 수 있는 평균

돌려 보면 5줄 4칸 → 4줄 4칸이 되고, 빈 금액 한 칸은 같은 메뉴(라떼)의 중앙값 5000으로 채워져요. 평균은 5125.0이 나와요. errors="coerce"는 숫자로 못 바꾸는 값을 오류 대신 빈 값으로 두라는 뜻이에요.

상황 1 · 빼느냐 채우느냐

빈 칸을 만나면 그 줄을 빼는 것과 값을 채우는 것 중에 골라야 해요. 줄이 아까우면 채우고, 채운 값이 결과를 흔들 것 같으면 빼요. 어느 쪽이든 무엇을 어떻게 했는지 적어 두는 것이 중요해요. 나중에 숫자가 이상할 때 여기부터 되짚게 되거든요.

상황 2 · 이름은 같지만 다른 전처리

CSS를 편하게 쓰게 해 주는 Sass 같은 도구를 CSS 전처리기라고 불러요. C 언어에도 #include를 처리하는 전처리기가 있고요. 데이터가 아니라 코드를 본 작업(컴파일·브라우저) 앞에서 다듬는다는 점에서, 이름이 붙은 이유는 같아요.

상황 3 · 전처리는 한 번으로 끝나지 않아요

분석하다 보면 "이 값은 빼야겠다" 같은 게 또 보여요. 그때마다 전처리 코드를 고쳐 처음부터 다시 돌려요. 그래서 전처리와 본 작업을 한 파일에 섞어 쓰기보다, 다듬기 따로 쓰기 따로 나눠 두는 편이 편해요. 전처리에 드는 시간이 본 작업보다 긴 경우도 흔해요.
