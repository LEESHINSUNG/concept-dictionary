Next.js

넥스트 제이에스

Next.js는 React로 웹사이트를 만들 때 필요한 것들을 미리 갖춰 둔 틀이에요. 가장 큰 몫은 서버에서 화면을 미리 그려 보내는 일이고요.

작성일 2026-10-22 카테고리 웹 › 프레임워크

1

쉽게 말하면

React가 레고 블록 한 봉지라면, Next.js는 블록에 설명서와 받침판, 바퀴까지 들어 있는 세트예요. 블록만 있으면 성을 지을 수야 있지만, 바닥은 뭘로 할지 문은 어떻게 달지를 매번 혼자 정해야 하죠.

React는 화면 그리는 일만 해요. 그래서 주소마다 다른 페이지를 보여 주기, 서버에서 미리 그려 보내기, 이미지 알아서 줄이기 같은 건 직접 붙여야 했어요. Next.js는 그걸 한 세트로 묶어 놨어요. 그래서 "React 프로젝트를 시작한다" 하면 대개 Next.js부터 꺼내요.

1React만 쓰면 브라우저가 빈 페이지를 받고 그때부터 그리기 시작해요. 첫 화면이 늦게 뜨고, 검색 엔진도 내용을 읽기 어려워요.

2Next.js는 같은 React 코드를 서버에서 먼저 실행해 완성된 HTML을 만들어 보내요. 그래서 도착하는 순간 글이 보여요. PHP 시절부터 쓰던 방식을 React로 되살린 셈이에요.

3브라우저에 도착한 뒤에는 React가 그 화면을 이어받아 클릭 반응을 맡아요. 처음엔 서버가, 그다음엔 브라우저가 담당하는 셈이에요.

3

예시로 보기

상황 1 · 파일을 만들면 주소가 생겨요

따로 설정을 적지 않아요. app/about/page.tsx 파일을 만들면 그대로 /about 주소가 돼요. 폴더 구조가 곧 사이트 구조라서, 처음 보는 프로젝트도 폴더만 훑으면 어떤 페이지가 있는지 알 수 있어요.

상황 2 · 검색에 걸려야 하는 사이트

쇼핑몰이나 블로그처럼 검색으로 사람이 들어와야 하는 사이트에 특히 좋아요. 서버가 내용을 채워 보내니 검색 엔진이 그대로 읽어 가거든요. 반대로 로그인 후에만 쓰는 사내 도구라면 굳이 필요하지 않을 수도 있어요.

상황 3 · 공짜로 얻는 것들

이미지를 화면 크기에 맞게 줄여 보내기, 쓰지 않는 코드 덜어 내기, 자주 안 바뀌는 페이지는 미리 만들어 두기. 혼자였다면 하나씩 붙였을 일들이 처음부터 들어 있어요.

React와 Next.js는 고르는 사이가 아니에요. Next.js 안에서 도는 게 React라서, React를 배우면 그대로 쓸 수 있어요.
