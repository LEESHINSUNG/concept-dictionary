React

리액트

React는 화면을 작은 조각으로 나눠 만들고, 데이터가 바뀌면 화면이 알아서 따라 바뀌게 해 주는 JavaScript 라이브러리예요.

작성일 2026-10-22 카테고리 웹 › 라이브러리

1

쉽게 말하면

레고를 떠올려 보세요. 큰 성을 한 덩어리로 깎는 대신 블록을 만들어 두고 조립하죠. 같은 블록을 여기저기 다시 쓸 수도 있고요. React는 화면을 그렇게 만들어요. 버튼, 카드, 목록을 컴포넌트라는 블록으로 만들어 두고 끼워 맞춰요.

더 큰 변화는 생각하는 방식이에요. 예전에는 "장바구니 숫자가 바뀌면 저 글자를 3으로 고쳐라"처럼 고칠 곳을 하나하나 지시했어요. 화면이 복잡해지면 고쳐야 할 곳을 빠뜨리기 쉬웠죠. React에서는 "장바구니에 3개가 있으면 화면은 이 모습"이라고 적어 두기만 해요. 달라진 곳을 찾아 고치는 건 React가 해요.

바뀐 화면

숫자만 3으로

1컴포넌트는 "지금 데이터가 이러면 화면은 이렇다"를 적어 둔 함수예요. 고치는 방법이 아니라 결과를 적는 거예요.

2데이터가 바뀌면 React가 그 함수를 다시 불러 새 모습을 만들어 보고, 지금 화면과 견줘요.

3달라진 부분만 골라 실제 화면에 반영해요. 그래서 개발자는 "무엇을 보여 줄지"만 신경 쓰면 돼요.

3

직접 해보기

누를 때마다 숫자가 올라가는 버튼이에요. React 코드의 모양을 보여 주기에 가장 짧은 예예요.

Counter.jsx

import { useState } from "react";

function Counter() {
  const [n, setN] = useState(0);   // 기억해 둘 데이터

  return (
    <button onClick={() => setN(n + 1)}>
      {n}번 눌렀어요
    </button>
  );
}

화면을 고치는 코드가 없어요

잘 보면 "버튼 글자를 바꿔라"는 줄이 어디에도 없어요. setN으로 숫자만 바꾸면 React가 알아서 글자를 다시 그려요. 이 한 가지가 React를 쓰는 가장 큰 이유예요.

React는 화면 그리는 일만 맡아요. 주소에 따라 다른 페이지를 보여 주거나 서버에서 미리 그려 보내는 일은 포함돼 있지 않아서, 보통 Next.js 같은 틀과 함께 써요.

한 줄 정리

데이터만 바꾸면, 화면은 알아서.
