쉽게 말하면

집을 지을 때를 떠올려 보세요. HTML이 벽과 방을 나누는 뼈대라면, CSS는 벽지와 가구 같은 꾸밈이고, JavaScript는 전기 배선이에요. 스위치를 누르면 불이 켜지는 것처럼 움직임을 담당해요.

버튼을 눌렀을 때 창이 뜨고, 글자를 입력하는 동안 검색어가 따라 나오고, 새로고침 없이 내용이 바뀌는 것 전부 JavaScript가 하는 일이에요. 이름 때문에 Java와 형제처럼 보이지만 이름만 비슷할 뿐 다른 언어예요. 인기 있던 이름에 얹어 간 마케팅의 흔적이에요.

보던 자리 그대로

1브라우저는 HTML을 받아 화면을 그린 뒤, 거기 딸려 온 JavaScript를 실행해요. 내 컴퓨터 안에서 도는 것이라 서버를 거치지 않아요.

2클릭이나 입력 같은 일이 생기면 미리 적어 둔 코드가 깨어나요. 필요하면 그때 서버에 데이터만 따로 물어보기도 해요.

3받은 결과로 이미 그려진 화면의 일부만 고쳐요. 페이지 전체를 다시 받지 않으니 깜빡임 없이 바뀌는 거예요.

직접 해보기

지금 보고 있는 이 페이지에서도 바로 해 볼 수 있어요. 브라우저에서 개발자 도구를 열고 콘솔에 적어 보세요.

브라우저 콘솔

document.title = "안녕!"
// 브라우저 탭에 적힌 제목이 그 자리에서 바뀌어요

document.body.style.background = "gold"
// 배경색도 바로 바뀌고요. 새로고침하면 원래대로 돌아와요

브라우저 밖에서도 돌아요

원래는 브라우저 전용이었지만, Node.js가 나오면서 서버에서도 쓰게 됐어요. 그래서 요즘은 앞단과 뒷단을 같은 언어로 만드는 일도 흔해요. 화면을 만들 때는 React 같은 도구를 얹어 쓰는 경우가 많고요. 터미널에서 node -e "console.log(1 + 1)"을 쳐 보면 브라우저 없이도 도는 걸 볼 수 있어요.

브라우저 안에서 도는 코드라 사용자가 열어 보고 고칠 수도 있어요. 그래서 비밀번호 검사 같은 중요한 판단은 JavaScript에만 맡기지 않고 서버에서 다시 확인해요. 쿠키에 HttpOnly를 붙이는 이유도 같아요.
