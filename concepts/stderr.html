표준에러

stderr · standard error

표준에러는 오류와 알림을 결과와 섞이지 않게 따로 내보내는 통로예요. 표준출력과 일부러 길을 나눠 둔 것이에요.

쉽게 말하면

공장에 출고구가 하나뿐이라면 어떻게 될까요. 완성품과 불량 보고서가 같은 상자에 섞여 트럭에 실릴 거예요. 받는 쪽은 매번 그걸 골라내야 하죠. 그래서 공장은 보통 출고구와 보고 창구를 따로 둬요.

프로그램도 그래서 길이 둘이에요. 계산 결과는 1번(표준출력)으로, "파일이 없어요" 같은 말은 2번(표준에러)으로 나가요. 덕분에 결과를 파일에 쌓는 동안에도 오류만은 화면에 바로 떠요. 일이 잘못됐는데 조용히 파일에 묻혀 버리면 알아차릴 수 없으니까요.

1프로그램은 이건 결과, 저건 오류를 스스로 구분해 각각 다른 번호로 내보내요.

2>로 길을 바꾸면 1번만 옮겨져요. 2번은 건드리지 않았으니 그대로 화면에 남아요. 오류를 따로 보내려면 2>라고 번호를 적어 줘야 해요.

3둘을 한곳에 모으고 싶으면 2>&1이라고 써요. "2번을 1번이 가는 곳으로 합쳐라"는 뜻이에요.

3

직접 해보기

없는 파일을 찾게 해서 오류를 일부러 내 볼게요.

터미널

$ ls 없는파일 > out.txt
ls: 없는파일: No such file or directory    # 여전히 화면에!

$ ls 없는파일 2> err.txt              # 2번을 파일로
$ cat err.txt
ls: 없는파일: No such file or directory

# 출력은 환경마다 조금 달라요

첫 줄이 이 개념의 전부예요

> out.txt로 길을 돌렸는데도 오류가 화면에 그대로 나왔죠. 1번만 옮겼기 때문이에요. 만약 길이 하나뿐이었다면 이 메시지는 out.txt 안에 섞여 들어가 아무도 못 봤을 거예요.

진행 상황도 2번으로 나와요

내려받기 진행률이나 "처리 중입니다" 같은 안내도 보통 2번으로 내보내요. 오류가 아니어도 결과물이 아니면 2번인 거예요. 그래야 결과를 파일로 받을 때 그런 글자가 섞이지 않아요.

이 1번과 2번이라는 숫자는 그냥 정한 게 아니라 운영체제가 통로에 붙여 주는 번호표, 곧 파일 디스크립터예요.

한 줄 정리

결과와 오류는, 다른 길로.
