데이터 사전 · data dictionary · データディクショナリ

데이터 딕셔너리는 데이터 항목 하나하나가 무슨 뜻이고 어떤 모양인지 적어 둔 사전이에요. 값을 담는 곳이 아니라 값에 대한 설명을 담는 곳이에요.

1

쉽게 말하면

회사 표에 cust_cd라는 칸이 있다고 해 볼게요. 처음 보는 사람은 이게 뭔지 알 수가 없어요. 고객 코드인 것 같긴 한데 몇 자리인지, 숫자인지 글자인지, 탈퇴한 고객도 들어 있는지 모르죠. 만든 사람한테 물어봐야 하는데 그 사람은 이미 퇴사했어요.

그래서 칸마다 설명을 적어 두는 사전을 만들어요. 이름이 무엇이고, 무슨 뜻이고, 어떤 값이 들어갈 수 있고, 누가 관리하는지요. 국어사전이 낱말을 설명하듯, 데이터 딕셔너리는 데이터 항목을 설명해요.

담는 것

값이 아니라 값의 설명

누가 보나

만드는 사람과 쓰는 사람

없으면

같은 이름이 다른 뜻이 돼요

그림으로 보기

항목 하나에 이런 내용이 붙어요. 값은 한 줄도 없고 전부 설명이에요.

고객코드 · cust_cd

뜻 우리 회사가 고객 한 명에게 붙이는 고유 번호
모양 영문 대문자 1자 + 숫자 7자 (예: C0001234)
허용 값 첫 글자는 개인 C 또는 법인 B
빈 값 허용하지 않음
만드는 곳 회원 가입 화면 (회원 시스템)
쓰는 곳 주문·배송·상담 시스템
관리 담당 회원 운영팀
주의 탈퇴해도 번호는 다시 쓰지 않음

01말이 통해요

"고객 수"를 세자고 할 때 탈퇴한 사람을 넣을지 뺄지가 사전에 적혀 있으면 다툴 일이 없어요.

02고칠 때 덜 무서워요

이 칸을 어디서 쓰는지 적혀 있으면, 고쳤을 때 무엇이 같이 망가지는지를 미리 알 수 있어요.

03새로 온 사람이 빨라져요

칸 이름만 보고 짐작하지 않아도 돼요. 짐작은 거의 틀려요.

04검사를 걸 수 있어요

허용 값이 정해져 있으면 그대로 입력 검사 규칙으로 옮길 수 있어요.

1데이터베이스 관리 시스템이 스스로 가지고 있는 시스템 카탈로그도 데이터 딕셔너리의 하나예요. 어떤 표에 어떤 칸이 있는지를 시스템이 적어 두는 거예요.

2다만 시스템 카탈로그에는 "무슨 뜻인지"가 없어요. 자료형과 길이는 알아도 업무상 의미는 사람이 적어 넣어야 해요.

3사전이 실제와 어긋나면 없느니만 못해요. 칸을 고칠 때 사전도 같이 고치는 절차가 없으면 아무도 믿지 않는 문서가 돼요.

같은 이름, 다른 뜻

영업팀의 "회원 수"는 가입한 사람 전부였고, 운영팀의 "회원 수"는 최근 석 달 안에 접속한 사람이었다고 해 볼게요. 둘 다 "회원 수"라고 부르니 보고서에 나란히 놓이면 숫자가 안 맞아요. 사전에 두 이름을 다르게 적어 두는 것만으로 이런 일이 사라져요.

메타데이터와 무엇이 다른가

메타데이터는 데이터를 설명하는 데이터를 가리키는 넓은 말이에요. 데이터 딕셔너리는 그중에서도 항목의 정의를 모아 둔 문서나 시스템을 가리켜요. 메타데이터가 재료라면 딕셔너리는 그 재료로 만든 사전이라고 보면 돼요.

창고가 커질수록 사전이 중요해져요. 데이터 웨어하우스나 데이터 마트를 여럿 두면, 같은 이름이 창고마다 다른 뜻이 되기 쉽거든요.
